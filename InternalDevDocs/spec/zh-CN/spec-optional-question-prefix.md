## 概述
[summary]: #summary

本规范把交互窗口（interactive window）中用于表示打印表达式的前导问号，对值引用（value reference）改为可选。当一次提交（submission）的末条语句是一个裸表达式——一个不以 `?` 开头的表达式——编译器按其绑定后结果的形状对该表达式分类。绑定为值引用——局部变量、字段、参数、属性访问或后期绑定属性组——的表达式被求值，其值被打印，与它写成带前导 `?` 时完全一样。绑定为方法组（method group）或调用（invocation）的表达式保留其现有的语句语义：不带括号的 `Sub` 调用仍然是一次调用，有副作用的调用保留其副作用。

本特性保留今天每一条合法语句的含义。赋值、声明与调用不变；只有此前无法通过编译的裸值引用现在会打印它的值。该行为限于交互窗口。脚本文件中末尾的裸表达式被接受并被忽略：它不被打印，也不设置进程退出码，退出码仍然只由入口点决定。

C# 交互窗口已经能在没有前缀的情况下打印裸表达式，而 C# 脚本方言（scripting dialect）是唯一一个末尾表达式产生结果的 C# 方言；普通的 C# 有意与它的脚本方言保持距离，正如 [LDM-2020-04-15][ldm-2020-04-15] 所记录。本特性为 Visual Basic 采用同样的编译器层面处理方式。

## 动机
[motivation]: #motivation

在今天的交互窗口中，求值一个表达式需要 `?` 前缀。`? Now` 打印 `Now` 的值；单独的 `Now` 产生编译时错误 BC30545，"property access must assign to the property or use its value."。对交互求值而言，这个错误是噪声。用户键入的是一个表达式，想要看到的是它的值；编译器却要求把该值赋出去或消费掉。

C# 交互窗口没有这样的要求。键入 `DateTime.Now` 会求值该表达式并在没有前缀的情况下打印其值。这是两个交互窗口之间最显眼的交互差距，也是新用户最可能碰到的第一个错误：从 C# 交互窗口、PowerShell 或交互式笔记本（notebook）迁移过来的用户习惯性地裸键入一个表达式，却收到一条对其后该做什么没有任何交代的编译器错误。

预期的结果是，「键入一个表达式，得到它的值」成为 Visual Basic 交互窗口的直觉行为。`?` 前缀对偏好它的用户仍然可用，其含义不变。因为本特性只改变此前无法通过编译的语句，所以没有任何现有会话的行为会有所不同。

## 详细设计
[design]: #detailed-design

### `?` 打印语句

交互窗口识别一种遗留的打印语句：首个标记为问号的语句。`?` 表示一个由宿主求值并打印的表达式。该表达式作为 R 值（R-value）被绑定，该语句是一条打印语句，而打印语句总是产生一个提交结果，宿主通过它的值格式化器（value formatter）打印该结果。

```vbnet
> ? Now
' 2026-08-14 12:34:56
> ? 1 + 2
' 3
```

打印语句为交互窗口独有。在普通编译中，前导问号不是合法的语句起始，被报告为一个意外的表达式语句（BC31003）。本特性不改变打印语句。

### 裸末尾表达式的分类

不以 `?` 开头的一次提交被解析为普通的顶层（top-level）脚本代码。当该提交的末条语句是一个表达式语句——一个裸表达式——时，编译器绑定该表达式并对绑定后的结果分类：

- **产出值的形状。** 绑定为值引用——局部变量、字段、参数、属性访问或后期绑定属性组——或绑定为计算所得值（例如字面文本或二元表达式）的表达式被求值，其值成为提交结果，由宿主打印。对于属性访问或后期绑定属性组，报告未使用属性访问的诊断对末条语句被抑制，该表达式作为 R 值被绑定。
- **调用形状。** 绑定为方法组或调用的表达式被当作调用语句处理。方法组被重新归类为一次无实参调用。`Void` 调用仍然是合法语句，不被打印。非 `Void` 调用产生一个提交结果并打印，与今天完全一样。

下表概括了提交末尾的可观察行为。分类锚定在绑定后结果的形状上，而不是表达式的文本上，也不是错误码清单上。

| 提交 | 绑定形状 | 提交末尾的行为 |
|---|---|---|
| `Now` | 属性访问 | 打印 |
| `DateTime.Now` | 属性访问 | 打印 |
| `before` | 局部变量 | 打印 |
| `1 + 2` | 表达式值 | 打印：`3` |
| `x > 5` | 表达式值 | 打印：`False` |
| `"a" & "b"` | 表达式值 | 打印：`"ab"` |
| `MySub` | 方法组，`Sub` → 无实参调用 | 合法语句，不打印 |
| `Console.WriteLine("hi")` | 调用，`Void` | 合法语句，不打印 |
| `SomeFunction()` | 调用，非 `Void` | 合法语句；照今天打印 |
| `x = 5` | 赋值 | 合法语句，不打印 |

### 值引用

值引用是其值为一个值的绑定后表达式：局部变量、字段、参数、属性访问，或成员组是属性组的后期绑定调用。这些形状出现在提交的末条语句位置时被求值并打印。

对于属性访问与后期绑定属性组，报告未使用属性访问的错误（BC30545）对末条语句被抑制，该表达式作为 R 值被绑定。其余形状绑定时无诊断。

```vbnet
> Now
' 2026-08-14 12:34:56
> DateTime.Now
' 2026-08-14 12:34:56
```

### 计算所得表达式

语句开头的字面文本或二元表达式此前会被误解析：像 `1 + 2` 这样的前导数值字面文本被解析为标签，而像 `x > 5` 这样带后缀二元运算符的前导标识符被误解析为一次调用。在脚本的顶层，这些现在被解析为表达式语句。它们作为普通值绑定，不产生「值被丢弃」诊断，并在提交末尾打印。

```vbnet
> 1 + 2
' 3
> x > 5
' False
> "a" & "b"
' "ab"
```

### 调用与方法组

一次调用绑定为一个已绑定调用（bound invocation），或者，对于 `Object` 接收者上的后期绑定成员访问，绑定为一个后期绑定成员访问。方法组是对一个或多个方法的引用，不是对值的引用；在语句开头它被重新归类为一次无实参调用。

这些形状中没有一个是本特性新增打印的。`Void` 调用——不带括号的 `Sub` 调用或有副作用的 `Sub` 调用——仍然是合法语句，不产生提交结果。非 `Void` 调用仍然是产生提交结果并打印的合法语句，与今天完全一样。

```vbnet
> MySub
' the Sub runs; nothing is printed
> Console.WriteLine("hi")
' the line is written; nothing else is printed
```

方法组的重新归类让不带括号的 `Sub` 调用得以保留：在交互窗口键入一个 `Sub` 的名字会调用它而不打印，这正是 Visual Basic 用户期待的行为。`Object` 接收者上的后期绑定成员访问绑定为一次调用，不被打印；交互窗口目前对末尾的后期绑定成员访问报告 BC30491，因为提交结果路径把该访问当作一个值。这是既有行为，不属于本特性。

### 裸变量引用

裸变量引用是值引用，会被打印。在

```vbnet
> Dim before = Now
```

之后键入 `before` 会打印所存的值：

```vbnet
> before
' 2026-08-14 12:34:56
```

这使交互窗口与 C# 交互窗口对齐，在后者中键入一个变量名会打印它的值。裸标识符在语法上于变量引用与方法名之间含混；两者在绑定时刻区分，此时标识符要么绑定为值引用，要么绑定为方法组。

### 解析前导裸表达式

在顶层脚本代码中，前导裸表达式被解析为表达式语句。两处含混在解析时刻解决：

- 紧跟一个冒号的裸数值字面文本是标签（`1:`）；一个裸数值表达式是表达式语句（`1 + 2`）。像 `True`、`Nothing` 或字符串这样的前导字面文本同样被解析为表达式语句。
- 裸标识符被解析为标识符表达式，以便变量引用与方法名在绑定时刻可区分。像 `DateTime.Now` 或 `obj.MySub` 这样的成员访问保留其调用形状，从而保留不带括号的成员 `Sub` 调用（`obj.MySub`）作为合法语句。

该行为以顶层脚本代码为门。普通编译，以及脚本文件中嵌套方法之内的代码，照旧解析与绑定：在普通编译中，前导的 `1 + 2` 作为标签被报告（BC30801），方法内部的裸属性访问报告未使用属性访问错误（BC30545）。

### 只有末条语句产生结果

与 C# 脚本方言一致，只有一次提交的末条语句产生结果。不是末条语句的裸表达式仍然是错误；它被报告为一个意外的表达式语句（BC31003），并且该提交不运行。

```vbnet
> 1 + 2 : x = 5
' Error BC31003: the bare expression is not the final statement
```

不是末条语句的成员访问继续报告未使用属性访问错误（BC30545），因为抑制只适用于末条语句。每次交互提交都作为独立的编译单元编译，所以「末条语句」逐次提交判定。延续会话的其后某次提交是一批全新的语句，它自己的末条语句符合条件。一次提交的末条语句，就是提交结果机制视为末尾的同一条语句，因此两种判定在构造上一致。

### 脚本模式与退出码

打印行为限于交互窗口。脚本的源代码种类同时服务交互提交与脚本文件，所以解析器与绑定器会接受脚本文件末尾的一个裸表达式。脚本文件中末尾的表达式不被打印，也不设置进程退出码。

脚本的退出码只由入口点决定：显式的 `Return value` 设置它，裸 `Return` 或执行落到代码末尾而不显式返回则把它设为 0。末尾表达式从来不是退出码的来源。这与普通编译中 `Function Main` 入口点的退出码语义正交；在两种模式下末尾表达式都不是退出码的来源。

## 健全性
[soundness]: #soundness

本特性所保留的不变式是：今天能编译的语句没有一条改变含义。行为改变的那些语句，仅仅是此前无法通过编译的语句的一个子集，而其中每一个都是从编译时错误变为一个被打印的值。

今天在交互窗口中合法的语句是赋值、声明、控制流语句与调用。赋值、声明与控制流语句不是表达式语句，绝不被本特性分类。一次调用绑定为一个已绑定调用，或者，对于不带括号的 `Sub` 调用，从方法组重新归类为一个已绑定调用；本特性不改变这些形状。因此 `Void` 调用仍然是不被打印的合法语句，非 `Void` 调用保留其产生提交结果的现有行为。两者都不变。

此前无法通过编译的语句，恰好就是交互窗口所拒绝的那些裸值引用与计算所得表达式：用作语句的属性访问（BC30545）、被解析器弄错形状的前导裸表达式——像 `1 + 2` 这样的前导字面文本被解析为标签，或者像 `x > 5` 这样带后缀二元运算符的前导标识符被误解析为一次调用——以及被解析器包装为一次调用的裸变量引用。对其中每一种，新行为都把该表达式作为 R 值绑定并打印其值，这正是用户通过在同样的表达式前写一个 `?` 就能获得的行为。本特性不引入新的求值语义；它把一个已有的显式操作变为隐含的。

显式的 `?` 前缀不变，所以本特性之后可达的每一种行为在此之前也可达。唯一的差别是先前错误的一个子集现在被静默求值。因为那个子集先前根本不产生任何程序——提交编译失败并且不运行——所以没有任何先前可观察的行为被移除。

## 缺点
[drawbacks]: #drawbacks

- **静默打印。** 一个此前无法通过编译的裸表达式现在打印一个值。如果用户想要的是一条语句——例如本想调用一个 `Sub` 却键入了属性名——编译时错误就被一个被打印的值取代，失误可能不被察觉。在交互窗口中，被打印的值本身就是一种反馈，但对揭示意图失误而言它弱于一个错误。

- **方言分歧。** 裸表达式在普通 Visual Basic 中不是合法语句。让它在交互窗口中打印，会增大交互方言（interactive dialect）与普通语言之间的差别，正如 C# 交互窗口已经不同于 C#。显式的 `?` 仍然可用，但先学会交互窗口的用户在写普通代码时必须把裸表达式这套习惯放下。

- **脚本模式的错误面。** 脚本文件中末尾的裸表达式从编译时错误变为一条被接受、被忽略的语句。依赖该错误的脚本或构建期检查必须更新。这是比照 C# 让 C# 与其脚本方言保持距离的决定而被接受的。

- **分类的维护。** 绑定结果形状的分类必须随着语言新增表达式形状而同步维护，以便新的值引用会打印、新的语句形状不被误分类。该分类是绑定模型的属性，不是错误码清单，这使这个面保持很小。

## 替代方案
[alternatives]: #alternatives

- **让 `?` 保持必需。** 不改变任何行为，但 BC30545 噪声以及与 C# 交互窗口的差距仍在。

- **改进错误消息。** 保持 `?` 必需，并把未使用属性访问错误改为建议用 `?`。风险更低，但没有让「键入一个表达式，得到一个值」变得直觉。

- **只打印续行的最后一个表达式。** 只在一行续行提交之后自动打印。范围更窄，但偏离了单行行为，也偏离了 C# 交互窗口。

- **打印每一条表达式语句。** 自动打印所有裸表达式，包括有副作用的调用。这一项经过考虑后被否决：它把静默行为的面扩大到每一条语句，并且会打印 `Sub` 调用的结果。

- **增加一个新的打印关键字。** 引入一种更明确的打印形式。这会重新引入本特性所消除的认知负担。

- **在宿主中改写提交的文本。** 在运行提交之前插入一个前导 `?`。这一项被搁置：编译器层面的处理保持单一绑定模型，使 IntelliSense 与错误恢复同解析出的树保持一致，并且不依赖宿主去识别哪些语句是表达式。

## 考量
[considerations]: #considerations

### 与 C# 交互窗口的对齐

C# 交互窗口在没有前缀的情况下打印裸表达式。在 C# 中，以一个产生结果的表达式结尾的能力限于脚本方言，并且主要在有交互环境的场合有意义；普通的 C# 有意不允许末尾表达式产生结果，C# 语言设计记录接受了 C# 与其脚本方言之间剩下的那段距离（[LDM-2020-04-15][ldm-2020-04-15]）。本特性为 Visual Basic 采用同样的编译器层面设定：交互提交的末尾表达式被绑定为产生一个结果，宿主通过 `?` 所用的同一条路径打印返回的值。不涉及宿主侧的文本改写。

### 交互方言

交互窗口是 Visual Basic 的一个独立方言，正如 C# 脚本是 C# 的一个独立方言。C# 设计记录反复指出不断扩张的脚本方言会使语言分裂的风险（[LDM-2019-09-11][ldm-2019-09-11]、[LDM-2020-02-26][ldm-2020-02-26]），以及脚本提交系统跨求值保留状态（[LDM-2020-01-22][ldm-2020-01-22]）。本特性停留在交互窗口之内，并为偏好显式 `?` 的用户保留它，所以交互方言与普通语言之间的差别仅限于把一个已有的显式操作变为可选。提交模型本身不变：每次提交是一次独立的编译，状态像今天一样跨提交保留。

### 脚本模式的错误面

因为脚本的源代码种类同时服务交互提交与脚本文件，解析器与绑定器无法区分两者。脚本文件中末尾的裸表达式因此被接受并被忽略，而不是作为错误报告。这是比照 C# 接受 C# 与其脚本方言之间距离的做法而被接受的。改变限于错误面：脚本的退出码不受影响，脚本文件嵌套方法内部的裸表达式仍然报告原来的错误。

### Option Strict

在 `Option Strict On` 与 `Option Strict Off` 之下，分类与打印路径相同。用作语句的裸表达式没有目标类型上下文，所以宽松类型模式的隐式转换不能应用于它。打印路径不做任何转换，只要求该值不是 `Void`。`Object` 接收者上的后期绑定成员访问绑定为一次调用，因此在两种设定下都不被打印。

### `?` 与关系运算符

在一条打印语句之内，表达式上下文就是普通的表达式上下文，其中 `=` 是关系相等运算符。因此 `? x = 5` 打印比较结果，而赋值写成一条语句，`x = 5`。两种形式在解析时刻区分，不冲突。

```vbnet
> ? x = 5
' False
```

## 测试
[testing]: #testing

本特性由无副作用的内存测试来演练：它们不进行网络访问、不写文件、不启动进程、不访问注册表。交互用例通过带捕获控制台的内存运行器运行；脚本用例只写入既有的隔离临时目录装置。

- **解析器测试。** 脚本顶层的裸表达式解析为表达式语句；`1:` 仍是标签；裸标识符解析为标识符表达式；成员访问保留其调用形状；普通编译不受影响。

- **语义测试。** 值引用绑定时无诊断并产生一个提交结果；方法组与 `Void` 调用作为语句绑定；不是末条语句的裸表达式报告 BC31003；不是末条语句的成员访问仍然报告 BC30545；在 `Option Strict On` 与 `Option Strict Off` 之下行为相同。

- **编译 API 测试。** 一个提交矩阵断言每一个是否产生提交结果：`1`、`Now`、`DateTime.Now`、`1 + 2` 与 `"a" & "b"` 产生；`x = 5`、`Dim i As Integer`、`Imports System`、`Console.WriteLine()` 与 `Sub Goo() End Sub` 不产生；`?1` 与 `?Console.WriteLine()` 继续产生。

- **端到端交互测试。** 内存运行器对 `Now`、`1 + 2`、`"a" & "b"`、一个裸比较以及一个裸变量引用断言被打印的值行以及无错误输出；对 `x = 5`、`Console.WriteLine("hi")`、一个不带括号的 `Sub` 调用以及一个复合赋值断言无值输出；断言 `? Now` 与 `? (1 + 2)` 不变；断言畸形输入（`Now x`）仍然报告错误；并断言不是末条语句的裸表达式报告 BC31003。多行续行的末条语句打印与单行提交一致。

- **脚本模式测试。** 含 `1 + 2` 或 `Now` 的脚本文件以退出码 0 退出且不产生输出；`? 21` 仍然退出 0；`Return 21` 仍然退出 21；裸 `Return` 仍然退出 0；脚本文件嵌套方法内部的裸表达式仍然报告原来的错误。

- **普通编译测试。** 方法内部的 `1 + 2` 仍然报告标签错误（BC30801）；`? 1` 仍然报告 BC31003；方法内部的裸属性访问仍然报告 BC30545；方法内部不带括号的 `Sub` 调用仍然合法。
