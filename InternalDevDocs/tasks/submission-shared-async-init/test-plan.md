# 怎么测：脚本共享挂钩的初始化时机（submission-shared-async-init）

判断依据与禁止事项见同目录 `README.md`。第一阶段**全是测量**，不许改产品代码。每格都要贴原始读数并标"跑出来的／读代码确认的／猜的"。

## 一、T1 读元数据属性位（核心）

放在 `Compilers\VisualBasicEmitTest\Emit\`，复用 `EmitMetadata.vb:605` 那套读 `row.Attributes` 的手段。

| 格 | 形状 | 期望（照实记，别预设） |
|---|---|---|
| T1-1 | 提交类：`Shared Event Ev` ＋ `Shared Sub H(...) Handles Me.Ev`（有共享挂钩） | 断 `BeforeFieldInit` 位**不在** `TypeAttributes` 里 |
| T1-2 | 提交类：只有 `Shared` 字段初始化器、没有任何 `Handles` | 该位**应当在**（这是普通 VB 语义，若被连带改掉说明抑制范围过宽） |
| T1-3 | 提交类：什么都没有 | 该位应当在 |
| T1-4 | 普通 `Class`（非脚本）带同样的 `Shared Event` + `Handles Me.Ev` | 与 T1-1 同结论 ⇒ 证明"提交类"没有特殊待遇，规则本来就一致 |
| T1-5 | 普通 `Module` 只含字段初始化器（作者说的 `Sub New` 惰性那种） | 该位在 ⇒ 把"为什么模块会惰性、类不会"钉成可读事实，而不是靠注释 |

## 二、T2 真正能鉴别的投递实验（核心）

要求：**除了一次静态方法调用之外，不触碰任何静态成员**。计数不能放 `Sink`（那是别的类型，会自己触发自己的初始化，白做）。

| 格 | 形状 | 判读 |
|---|---|---|
| T2-1 | 计数放进 `H` 自己的**共享字段**，但读取放在 raise **之前**的表达式里做不了 ⇒ 改法：把计数器做成一个实例对象的字段，由宿主对象在 raise 之后读 | 投递=1 ⇒ 时机正确；投递=0 ⇒ 挂钩没在 raise 前就绪 |
| T2-2 | 与 T2-1 同形状，但**故意去掉** `Shared` 挂钩、只留共享字段初始化器（构造一个应当惰性的对照） | 用来证明这套探针确实能区分"跑过/没跑过"（否则 T2-1 的结论无意义） |
| T2-3 | 记录 T1 与 T2 的交叉：位有/无 × 投递/不投递 四种组合各自出现在哪一格 | 表格化写进日志，作为"押注 CLR 语义"是否成立的判据 |
