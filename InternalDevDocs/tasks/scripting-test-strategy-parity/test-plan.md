# 验收矩阵（scripting-test-strategy-parity）

**只读取证先做，构建面独占后再动测试。** 档位与三态逐格标；档 3（读码）不得冒充档 1（已运行）。

## 一、SP-F01 策略对照（档 3 + 必要的只读统计）

| # | 交付 | 通过条件 |
|---|---|---|
| S1 | C# 侧脚本测试装置清单与用法 | `ScriptTestFixtures.cs` 是什么、被哪些用例引用（文件:行 + 引用计数）；C# 是否用它做容器/形态参数化 |
| S2 | VB 侧对偶物 | 明确结论：有 / 无；若无，VB 用什么替代（基类、helper、复制粘贴）并给 2–3 处实例 |
| S3 | **配对规则**差异 | 抽 C# 与 VB 各若干"脚本容器内拒绝某构造"的用例，统计**有多少负向格配了正向对照**（两侧各给分母/分子与比值），不许只给定性 |
| S4 | 三条缺陷的策略归因复核 | 逐条回答"当时有没有任何一条用例会在它被修好后变红"（即测试是否具备发现力）；结论给文件:行 |
| S5 | 受影响的既有格子数 | 按 S3 的口径在 `..\script-mode-coverage-parity\test-plan.md` 的矩阵里数出"只有负向证据"的格数（给检索式与命中数），作为口径修订的收益量化 |
| S6 | 策略差异四条维度表 | 装置 / 配对规则 / 容器参数化 / 断言粒度，每维「C# 做法 / VB 现状 / 对齐动作 / 成本」；无法对偶处写「有意分叉 + 理由」 |

## 二、SP-F02/F03 落地与补测试（档 1）

| # | 项 | 通过条件 |
|---|---|---|
| P1 | 装置对偶（或明确"不需要"并给理由） | VB 侧出现可复用的容器参数化入口；旧用例被其带走跑，不复制粘贴第三套写法 |
| P2 | 配对规则落成测试 | 三条缺陷各自的**正向语义**有钉：成员体内 `Me.字段` 取到字段、体内 `Me.ToString()` 取到 `Object` 成员、顶层自动属性 + 后随语句运行输出初值 |
| P3 | **发现力检验（关键）** | 每条新用例必须在**产品码未修**时红、修好后绿；逐条记录"当前是红还是绿"以及红在哪条诊断上。禁止写一条永远绿的空壳 |
| P4 | 断言粒度 | 新用例断具体值/符号（不接受只 `AssertDiagnostics`）；抽样给实数 |
| P5 | 定向实跑 | 受影响的测试类逐类跑（L1 `--filter`；L2 程序集 `-automated`），给真实计数与红/绿清单 |

## 三、SP-F04 回归（档 1 + 档 2，独占构建）
Q1 七门 gate（`scripts\verify-vb-compiler-tests.ps1`）Failed=0，基线以脚本内记录为权威、Total = 基线 + 新增用例数；Q2 `Scripting\VisualBasicTest` 全量 `-automated` Failed=0（P3 因产品未修而合法的例外必须逐条登记并标缺陷号，不得静默红）。

## 五、终局判据

3. Q1–Q2 绿（合法例外逐条登记）。
4. W1–W3 落账。
